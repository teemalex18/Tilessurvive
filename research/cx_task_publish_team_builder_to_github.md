и, если настроен, `gh`.

Выполни задачу полностью: диагностика репозитория, перенос файлов, проверки,
коммит, push и проверка GitHub Pages. Не ограничивайся инструкциями для
пользователя, если команды можно выполнить самостоятельно.

`D:\Projects\TilesSurvive\site\`.

## Главный результат

Локальный исходный файл:

## Важная архитектура

`Index.html` является автономным React-приложением.

Таблица силы из `research/battle_power_tables.json` минифицирована и встроена
в `Index.html` как:

```javascript
const BP = { ... };
```

Поэтому страница работает без сервера и без `fetch`.

Исходный JSON всё равно нужно опубликовать для аудита и последующих обновлений.

## Формула силы

```text
Сила героя =
  BattlePower уровня
  + BattlePower звёздного ранга
  + сумма BattlePower навыков
  + сумма BattlePower снаряжения
```

Формула верифицирована на реальных игровых значениях.

### Профили уровня и звёзд

Team Builder использует разные кривые:

| Профиль | Уровень 130 | 10 звёзд |
|---|---:|---:|
| SSR | 390289 | 1076911 |
| ORANGE | 390289 | 861533 |
| SR | 323955 | 538445 |
| R | 222488 | 323067 |

`ORANGE` применяется к героям с внутренним id, заканчивающимся на
`_orange`, например `lucky_orange`.

## Важные сопоставления героев

- Повар в UI использует реальные данные внутреннего героя `ken`.
- SSR Лаки использует `lucky_orange`.
- Titi в UI использует `tithi`.

Не менять эти сопоставления без отдельной проверки бинарных данных.

## Ограничения навыков

- Автоатака: уровни `0–40`.
- Боевой: уровни `0–40`.
- Пассивный: уровни `0–40`.
- Талант SR: уровни `0–3`.
- Талант SSR: уровни `0–4`.
- `null` в таблице BattlePower трактуется как вклад `0`.

## Работа с GitHub

1. Проверить доступ:

```powershell
git --version
gh auth status
```

2. Перейти в уже подготовленную рабочую копию:

```powershell
cd D:\Projects\TilesSurvive\site
git status
git branch --show-current
git remote -v
```

3. Обновить рабочую ветку через обычный `git pull --ff-only`.

4. Не копировать файлы повторно из других директорий. Папка `site` уже содержит
`index.html` в правильном регистре и готовую структуру `research\`.

5. Проверить текущую структуру репозитория и настройки GitHub Pages.
6. Не удалять существующие пользовательские файлы без необходимости.
7. Не коммитить:
   - `BinaryConfigPack.ss`;
   - `screenshots/`;
   - `__pycache__/`;
   - `.cx_*` временные профили браузеров;
   - игровые извлечённые бинарные файлы;
   - локальные абсолютные данные, не нужные для работы страницы.
8. Добавить или обновить `.gitignore`, если это необходимо.
9. До коммита проверить:

```powershell
git status --short
git diff --stat
git diff --check
```

10. Создать один понятный коммит.
11. Отправить изменения в ветку, используемую GitHub Pages.
12. Проверить опубликованную страницу после деплоя.

Рекомендуемое сообщение коммита:

```text
Publish verified Tiles Survive Team Builder
```
