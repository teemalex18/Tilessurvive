# Tiles Survive: документация проекта

**Актуально на:** 11 июня 2026 года

## 1. Кратко о проекте

Проект состоит из двух связанных частей:

1. **Рабочий Team Builder** — статическая веб-страница для настройки героев,
   расчёта их силы и сборки команды из пяти героев.
2. **Исследовательская часть** — Python-скрипты, извлечённые таблицы, скриншоты
   и отчёты, с помощью которых был разобран бинарный конфиг игры Tiles Survive.

Главный готовый пользовательский результат находится в
`site/index.html`. Исходная рабочая версия также лежит в корне как
`index.html`.

Team Builder считает именно показатель **BattlePower (силу)**. Он не
симулирует бой, урон, лечение или эффективность команды в конкретном режиме.

## 2. Что уже работает

### 2.1. Team Builder

В интерфейсе можно:

- отметить имеющихся героев;
- задать каждому герою уровень от 1 до 150; стартовое значение — 120;
- задать звёздный ранг от 0 до 10;
- указать уровни автоатаки, боевого, пассивного и талантного навыков;
- задать уровни трёх предметов снаряжения;
- собрать команду из пяти героев;
- увидеть силу каждого героя и общую силу команды;
- отфильтровать героев по классу, редкости и наличию;
- получить до шести предложений замены выбранного героя, отсортированных по
  рассчитанной силе;
- указать инвентарь из пяти предметов каждого типа и автоматически
  распределить его между героями команды;
- сохранять по явной кнопке список своих героев и их постоянные параметры;
- отдельно сохранять по явной кнопке инвентарь снаряжения;
- отфильтровать героев по фракции;
- увидеть бонус финального здоровья за фракционный состав;
- выбрать фракцию противника и учесть сопротивление фракций в оценочной силе.

Все расчёты выполняются в браузере. Сервер и база данных для работы страницы
не нужны.

### 2.2. Расчёт силы героя

Подтверждённая формула:

```text
Сила героя =
  BattlePower уровня
  + BattlePower звёздного ранга
  + сумма BattlePower выбранных уровней навыков
  + сумма BattlePower трёх предметов снаряжения
```

Если навык закрыт, выбран уровень `0` или в таблице находится `null`, его вклад
считается равным нулю.

Для уровней и звёзд используются отдельные кривые редкости:

| Профиль | Сила уровня 130 | Сила уровня 150 | Сила ранга 10 |
|---|---:|---:|---:|
| SSR | 390 289 | 640 000 | 1 076 911 |
| ORANGE | 390 289 | 640 000 | 861 533 |
| SR | 323 955 | 531 200 | 538 445 |
| R | 222 488 | 364 800 | 323 067 |

Профиль `ORANGE` применяется к внутренним героям с суффиксом `_orange`.

Особые сопоставления интерфейса с внутренними ID игры:

| Герой в интерфейсе | ID таблицы BattlePower |
|---|---|
| Chef | `ken` |
| Titi | `tithi` |
| Lucky SSR | `lucky_orange` |

Формула без снаряжения проверена по четырём игровым состояниям:

| Герой | Получено формулой | Значение на скриншоте | Статус |
|---|---:|---:|---|
| Becka | 534 042 | 534 042 | совпало |
| Tara | 476 601 | 476 601 | совпало |
| Rosie | 2 282 570 | 2 282 570 | совпало |
| Tarzan | 531 112 | 531 112 | совпало |

Для Rosie также подтверждён полный расчёт со снаряжением:

```text
2 282 570 + 1 028 947 + 722 465 + 894 942 = 4 928 924
```

### 2.3. Фракции и оценочная сила отряда

В проекте используются три фракции:

- Силачи;
- Разбойники;
- Воздухоплаватели.

Воздухоплаватели считаются героями любой фракции при расчёте группового
бонуса. Они автоматически распределяются между Силачами и Разбойниками так,
чтобы итоговый бонус был максимальным.

Подтверждённая таблица из игрового конфига `same_unit_type_add_up`:

| Размер группы одной фракции | Бонус финального здоровья |
|---:|---:|
| 1 | 0% |
| 2 | +2% |
| 3 | +8% |
| 4 | +15% |
| 5 | +25% |

Бонусы двух групп складываются. Например:

```text
2 Силача + 1 Воздухоплаватель + 2 Разбойника
-> Воздухоплаватель дополняет Силачей
-> группы 3 + 2
-> 8% + 2% = 10% финального здоровья
```

Сопротивление фракций даёт `+20%` урона против фракции, над которой есть
преимущество. Цикл: Разбойники сильнее Силачей, Силачи сильнее
Воздухоплавателей, Воздухоплаватели сильнее Разбойников. Для расчёта
пользователь выбирает фракцию противника.

Игра не хранит прямого перевода бонуса финального здоровья или урона в
`BattlePower`. Поэтому Team Builder показывает:

- **базовую силу** — точную сумму игровых значений BattlePower;
- **оценочную силу отряда** — базовую силу с применёнными процентами синергии
  и сопротивления для сравнения составов.

Текущая оценочная формула:

```text
Оценочная сила =
  базовая сила
  + базовая сила × бонус финального здоровья
  + сумма силы героев с преимуществом × 20%
```

Это сравнительная метрика Team Builder, а не отображаемый игрой BattlePower.

### 2.4. Автоматическое распределение снаряжения

Пользователь вводит до пяти уровней шлемов, жилетов и сапог. Для каждого типа
предметы сортируются от сильного к слабому и раздаются героям текущей команды.

Приоритеты заданы вручную:

- Guardian в первую очередь получает жилет;
- Gunner и Marksman — шлем;
- Support — жилет;
- Chef и Layla имеют отдельный приоритет на сапоги.

Внутри одинакового приоритета более сильный герой получает лучший предмет.
Это эвристика интерфейса, а не доказанный игровой алгоритм оптимизации.

### 2.5. Исследование игровых конфигов

Разобран контейнер `BinaryConfigPack.ss` и внутренний формат CFG:

- найден заголовок и таблица страниц пака;
- разобраны row ID, записи, схемы полей и self-relative указатели;
- найдены таблицы героев, уровней, рангов, навыков, эффектов, снаряжения,
  боевых коэффициентов и свойств;
- написаны скрипты для дампа и анализа записей;
- выгружены таблицы BattlePower;
- исследованы отображаемые проценты PVE-эффектов навыков.

Основной технический отчёт по структурам: `report_tiles_survive.md`.

## 4. Как данные попадают в Team Builder

Конвейер обновления:

```text
BinaryConfigPack.ss
  -> cx_export_battle_power.py
  -> research/battle_power_tables.json
  -> cx_add_rarity_bp_tables.py
  -> cx_update_team_builder.py
  -> const BP внутри index.html
```

### Шаг 1. Базовая выгрузка

`cx_export_battle_power.py` читает бинарный пак и создаёт
`research/battle_power_tables.json`. Скрипт выгружает уровни, ранги, навыки и
снаряжение и выполняет встроенные контрольные проверки.

### Шаг 2. Кривые редкости

`cx_add_rarity_bp_tables.py` добавляет отдельные таблицы уровней и рангов для
`SSR`, `ORANGE`, `SR` и `R`.

### Шаг 3. Встраивание в страницу

`cx_update_team_builder.py` минифицирует JSON и заменяет объект
`const BP = {...}` внутри корневого `index.html`. Затем он проверяет четыре
контрольных расчёта и пишет результат в `cx_update_team_builder_report.txt`.

В `site/index.html` данные уже встроены. Страница не делает `fetch` и не
зависит от отдельного JSON во время работы.

## 5. Архитектура веб-страницы

`site/index.html` — одностраничное React-приложение:

- React 18 и ReactDOM загружаются с `unpkg.com`;
- Babel загружается с `unpkg.com` и компилирует JSX в браузере;
- Tailwind CSS загружается с `cdn.tailwindcss.com`;
- данные BattlePower встроены в HTML;
- рабочее состояние хранится в React `useState`;
- профили своих героев и инвентарь сохраняются в `localStorage` только после
  явного нажатия соответствующей кнопки.

Практические последствия:

- страницу можно разместить на GitHub Pages как статический файл;
- отдельный backend не требуется;
- для загрузки React, Babel и Tailwind нужен доступ к интернету;
- после обновления страницы сохранённые профили героев и сохранённый инвентарь
  загружаются автоматически;
- профиль героя содержит принадлежность коллекции, уровень, звёзды, навыки и
  сигнатурное оружие;
- временно назначенная герою экипировка не входит в профиль героя;
- общий инвентарь снаряжения хранится отдельно от профилей героев;
- текущий состав команды не сохраняется;
- данные локальны для конкретного браузера и не синхронизируются между
  устройствами.

## 7. Что подтверждено, а что нет

### Подтверждено

- формула BattlePower героя;
- вклад уровня, полного звёздного ранга, навыков и снаряжения;
- четыре контрольных расчёта без снаряжения;
- полный расчёт Rosie со снаряжением;
- структура основных CFG-таблиц;
- таблицы силы для уровней, редкостей, навыков и золотой экипировки;
- наличие PVE-значений эффектов в `PveEffect` и `PveNewEffect`.

### Частично подтверждено

- извлечение процентов эффектов навыков: для пяти контрольных эффектов
  подтверждено использование `EffectParam2` с масштабом `/10` или `/100`, но
  универсальное правило выбора масштаба пока не найдено;
- описания героев и навыков в `data/` заполнены только для части героев;
- правила обычного роста характеристик экипировки между контрольными уровнями
  отдельно не подтверждены в черновом `data/gear_rules.json`.

### Не является расчётом игры

- tier-рейтинг героев;
- рекомендации по ролям;
- автораздача экипировки;
- перевод фракционных боевых процентов в оценочную силу отряда;
- предложения замены героя учитывают только текущую рассчитанную силу, а не
  лечение, контроль, позиционирование или взаимодействие навыков.

## 8. Известные ограничения

- Team Builder показывает 25 героев, тогда как BattlePower выгружен для 35
  внутренних героев.
- Некоторые отображаемые герои используют сопоставление с другим внутренним
  ID; для неизвестного ID отсутствующие значения дают вклад `0`.
- Сохранённые профили и инвентарь могут исчезнуть после очистки данных сайта
  или при использовании приватного режима браузера.
- Страница зависит от внешних CDN.
- В расчёт не входят эксклюзивное оружие, скрытые бонусы аккаунта, глобальные
  бафы, частичные сегменты текущей звезды и боевые взаимодействия.
- Фракционная синергия не меняет базовый BattlePower, но учитывается в
  отдельной оценочной силе отряда.
- Автораздача экипировки не ищет математически лучший состав и не оценивает
  реальную эффективность боя.
- `research/skills_final.json` и старые отчёты по UI-процентам нельзя считать
  полностью достоверными: в ходе исследования был найден неверный подход,
  смешивавший SLG-параметры описания и PVE-значения.
- Последний сохранённый отчёт обновления данных отмечает проверку данных как
  `PASSED`, а браузерную проверку как `PENDING`.

## 9. Как запустить

Открыть `site/index.html` в браузере или опубликовать содержимое `site/` через
GitHub Pages.

Из-за внешних CDN при локальном открытии нужен интернет.

## 10. Как обновить данные

Обновление выполняется из корня исследовательского проекта, где доступен
игровой пак:

```powershell
cd D:\Projects\TilesSurvive
python cx_export_battle_power.py
python cx_add_rarity_bp_tables.py
python cx_update_team_builder.py
```

После этого нужно перенести обновлённые `index.html`,
`research/battle_power_tables.json` и отчёт в `site/`, проверить страницу и
только затем публиковать.

Скрипты публикационной папки компилируются без синтаксических ошибок:

```powershell
cd D:\Projects\TilesSurvive\site
python -m py_compile cx_export_battle_power.py cx_add_rarity_bp_tables.py cx_update_team_builder.py
```

Не следует запускать полную регенерацию непосредственно из `site/`: игровой
пак намеренно не находится в публикуемом репозитории.
